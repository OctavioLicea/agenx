## Decisiones tomadas

- **MCP de Supabase — falsa alarma resuelta**: el proyecto "NYOWedding"
  (org "Octavio's Wedding.Org") SÍ es el correcto — ahí vive el schema
  `tuasesor` como instancia compartida. La sospecha de Sesión 14 nació
  de un `list_tables` sin especificar schema (trajo solo tablas de
  `public`, de la app hermana). Confirmado por Okta con captura directa
  del SQL Editor de Supabase. Lección: siempre pedir el schema
  `tuasesor` explícitamente al usar este MCP en el repo.
- **No se aceptan credenciales de GitHub**: Okta preguntó cómo pasar
  credenciales para que Claude hiciera el push/deploy directo — se
  explicó que eso está fuera de política (nunca se manejan tokens/
  contraseñas), y que además no resolvería nada (`npm run deploy` usa
  el `git push` ya autenticado en la máquina de Okta, no un conector de
  API). El deploy se queda manual desde su equipo.
- **Nuevo método para verificar builds en Cowork**: copiar el repo
  (excluyendo `node_modules` y `.git`) a una carpeta temporal fuera del
  repo, correr `npm install` ahí (para bajar binarios nativos de Linux
  de Rolldown/Vite, distintos a los de Windows) y `npm run build` ahí.
  Es la primera vez que se logra compilar de verdad dentro de Cowork en
  vez de depender de que Okta lo haga en su máquina. Regla dura:
  **nunca correr `npm install` sobre la carpeta real montada** — le
  metería binarios de Linux y rompería `npm run dev`/`build` en
  Windows.
- **Regla dura nueva sobre el bug de sync del sandbox**: NUNCA usar
  "leer un archivo con bash y reescribirlo" como forma de forzar que
  git detecte un cambio hecho por la herramienta de edición real — si
  la lectura de bash está obsoleta en ese momento (bug ya documentado
  desde Sesión 12), se reescribe el archivo real con contenido viejo/
  truncado. Pasó exactamente eso hoy con 4 archivos. La forma segura de
  forzar que git vea un cambio es escribir contenido ya verificado
  (`git show` de un commit bueno, o una copia de respaldo) directamente
  encima, sin releer el archivo actual por bash.
